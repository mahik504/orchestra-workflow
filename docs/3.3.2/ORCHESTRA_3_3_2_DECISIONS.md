## WHAT ORCHESTRA 3.3.2 WILL DO BETTER THAN 3.3.1

Ranked by output impact. Cap 15.

1. **Layer A: live-app Playwright owns objective pass/fail** — mock screenshots stop pretending to be QA (A, B, D, E, I). Perception is Layer B, not Playwright-as-taste.
2. **Hosts, conductor, `.cursorrules`, and skill allowlist match the repo** — the four job-loaded skills actually exist live (all classes).
3. **Independent judge only when triggers fire** — not because the run is FULL; CRUD stays cheap (A/B/E vs F/G/H).
4. **Worker capsules + token ladder** — fewer wrong files, less Brain dump (G especially).
5. **Classified failures + retry that changes something** — no identical blind loops (all).
6. **Anti-slop as missing decisions + 2026 cliché calibration** — flagship UI stops looking like Inter/#000 grep leftovers (A, B, E, I).
7. **3–5 lightweight directions on flagship, one implementation** — composition/type/motion, not five palettes or five sites (A, B, E; class C path).
8. **Mission file with immutable acceptance + derived execution budget** — the run cannot quietly rewrite DoD or default to max spend.
9. **Capability → model / reasoning / host / tool recommendation** — no silent weak provider; no silent quality downgrade; OpenDesign never selected as conductor.
10. **Honest registry and overlay** — unverified stays unverified; empty eval arrays cannot claim thousands.
11. **Human gate specified** — identity, direction, destructive, security, deploy, missing acceptance, material tool/model gap.
12. **LIGHT intensity** — CRUD/debug/API skip Design Lab tax (F, G, H).
13. **Two-layer visual QA, one browser owner** — stills, then Layer A, then Layer B when budgeted; duplicate browsers collapsed.
14. **Optional OpenDesign as a later visual worker** — only if it improves A/B stills, never as core.
15. **Memory classes + 3I hygiene classes** — Brain stays overlay; dead modules do not ship as “active.”

## 3C implementation decisions

Recorded when the runtime landed. Spec adopt/reject lists above still govern 3D–3I.

| Decision | Why |
| --- | --- |
| New package `runtime/internal/mission`, not a second engine | Six 3C concepts only. The 8-stage pipeline remains the executor. |
| Filesystem `.orchestra/runs/<id>/` | Reuses existing `.orchestra` layout. Refuses SQLite / DAG / job OS. |
| Derived budget with hard `retry_budget` ceiling 4 | Bound retries without a universal N or quality-bar presets. |
| `visual_review` / `independent_judge` stored, not executed | 3D owns Layer A/B and the judge. 3C must not pretend they ran. |
| Retry requires a change; identical signature stops | Tenet/Ralph/Zenith stop rule. Human-needed and specification never auto-retry. |
| `ErrHumanGateRequired` sentinel kept for equality | Existing tests use `err != ErrHumanGateRequired`. Reason lives on run state `pending_human`. |
| Intensity LIGHT/FULL on the mission | Orthogonal to STANDARD/PREMIUM/EXPERIMENTAL. No fourth bar. |
| Capsule holds paths and skill **ids**, never catalogs or chat | Token ladder. `ScopeReport` makes size inspectable. |
| Provider tokens banned on structural JSON | Contracts stay host-neutral. User objective text is not scanned as a leak. |
| Visual iterate loop unchanged | Self-heal tests pin `MaxIterations` and `ErrMaxIterationsExceeded`. 3C records classes onto run state instead of replacing Stage 8. |
| Iterate `pending_human` only when Stage 8 is exhausted | 3C.1: identical QA misses during a heal must not leave a blocking human gate on SUCCESS. |
