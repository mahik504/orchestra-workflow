# Ship

When a project is **done enough to show**:

1. Stop. Remind: `git push`, then LinkedIn/Instagram only if you drafted a caption.
2. Write `projects/<slug>/ship-post.md` from `templates/ship-post.md`. Concrete. No fake stars or users.
3. Do not start the next product in the same breath.

Public repos get real commits only. No contribution-graph generators. The private vault heartbeat is owner-approved and out of scope. Every new public repo gets a LICENSE the same day.

Agent-Reach may read the operator's own profiles for a visibility audit. Posting stays manual. GitHub profile README is a public repo named exactly the user's GitHub username.

## Publishing standard

The README names what the thing does, how to install it, and how to remove it. Diagrams come from the renderer, not a second chart library. The changelog says what changed and what was not measured. Topics and the About line stay under the host's limits. You draft the post. The human publishes it. No fake star count, no "proud to announce."

## Preconditions

- The project runs, and a command has already checked the thing being shown.

## Procedure

1. The task's paths and acceptance line win.
2. Remind the operator to push. Draft the post. Do not publish it.
3. A new public repo gets a LICENSE the same day.

## Output

The draft path and the command output that showed the project works.

## Verify

The draft contains no invented user count, star count, or score.

## Skip

Skip when the task is a one-file fix, or when the operator said not to draft a post.
