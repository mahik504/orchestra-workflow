# Design intelligence

Run this before `taste-design` on a PREMIUM or FLAGSHIP surface. The output is a one-page direction the contract can absorb.

## Write these lines

| Line | What to decide |
| --- | --- |
| Audience | Who the page is for, in one sentence |
| Reference | One to three named sites or screens, plus what you are taking (type scale, grid, motion) |
| Type | One display face, one text face, the sizes you will actually use |
| Color | Paper, ink, one accent. Say why the accent is there |
| Layout | The column logic and the one unusual move |
| Motion | Which runtime owns it. GSAP owns scroll. A second engine needs a reason |
| Not this | The template look you are refusing (generic purple gradient, equal three-column cards, unmotivated glass) |

## Then

Hand the page to `taste-design`. One `DESIGN.md`. Do not open a second design system. Do not copy assets, copy, or a logo from a reference.

## Bookmarks

Public galleries (Godly, Awwwards, SiteInspire, Lapa, Mobbin, Refero, Codrops) are places to look. A gallery is not a component to paste. Name the screen and the decision it supports.


## Preconditions

- The task names the files or the acceptance line.

## Procedure

1. The task's paths and acceptance line win.
2. Name type, color, layout, and motion. Then stop for taste-design.

## Output

The change, the command that checked it, and what that command printed.

## Verify

Say the work is done only after that command has been run.

## Skip

Skip when the human says skip orchestra. Do not add a second conductor.
